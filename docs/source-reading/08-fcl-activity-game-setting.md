# fcl：根目录与 activity / game / setting / fragment / upgrade / terracotta / scoped / util

范围：`FCL/src/main/java/com/tungsten/fcl/` 根目录直接文件（FCLApp 等）与 activity（7 文件）、game（23 文件）、setting（15 文件）、fragment（2 文件）、upgrade（4 文件）、terracotta（6 文件）、scoped（1 文件）、util（9 文件），共约 13.3K 行。

## 一、Application 与全局初始化时序

**FCLApp**（`FCL/src/main/java/com/tungsten/fcl/FCLApp.java`，Manifest 中 `android:name=".FCLApp"`）异常轻量：`attachBaseContext` 中即赋 `instance`（早于任何 Activity/ContentProvider，注释明确说明这是为了让全局随时可用）；`onCreate` 只注册 `ActivityLifecycleCallbacks`，用 `WeakReference<Activity>` 跟踪 `currentActivity`（onCreated/onStarted 更新、onDestroyed 置空），供 `Controller.showUpgradeDialog`、`LauncherHelper` 的 autoExitLauncher 等处拿"当前 Activity"。StrictMode 代码被注释停用。**真正的重初始化（ConfigHolder/RendererManager/Logging/Controllers/Profiles/Accounts）不在 Application，而是分散在 SplashActivity 和 MainActivity**——原因是强杀进程后可能不经过 Splash 直接落到 MainActivity，因此 MainActivity.onCreate 里有 `if (!ConfigHolder.isInit()) { ConfigHolder.init(); RendererManager.init(...) }` 的兜底双保险。ThemeEngine 位于 fcllibrary（见 [11-fcllibrary.md](11-fcllibrary.md)），各页面通过 `ThemeEngine.getInstance().addRefreshListener/removeRefreshListener` 订阅主题刷新。

## 二、启动链路：SplashActivity → RuntimeFragment → MainActivity

**SplashActivity**（入口 Activity，含 `.ImportActivity` activity-alias 处理 ACTION_VIEW 整合包）：1) EULA 未同意则弹不可取消对话框（写 `isAgree`）；2) 权限：R+ 走 `Environment.isExternalStorageManager()`（MANAGE_EXTERNAL_STORAGE），旧版本走读写存储运行时权限，被永久拒绝时引导到应用详情页；3) `init()` 在 IO 协程依次 `FCLPath.loadPaths`（fclauncher 侧路径表）、`Logging.start`、`initState()`。`initState` 用 `RuntimeUtils.isLatest(目标目录, assets 路径)` 对比 `version` 文件判断 8 项运行时是否就绪（LWJGL 3.3.3/3.4.1、Caciocavallo 8/17、JRE 8/17/21/25、JNA），并生成游戏用的 `resolv.conf`（系统 DNS 过滤掉 IPv6——注释说明 JNDI DNS 解析不了裸 IPv6——再按地区追加 223.5.5.5/119.29.29.29 或 1.1.1.1/1.0.0.1，内容一致时不覆写）。全部就绪 → `enterLauncher()`；否则 `start()`：首次启动进 **EulaFragment**（阅读 eula.txt，点下一步写 `isFirstLaunch=false` 回调 `SplashActivity.start()`），否则进 **RuntimeFragment**。RuntimeFragment 逐项展示就绪状态，点安装后用 `RuntimeUtils.install/installJava/installJna` 解压 assets（Java 是 `universal.tar.xz + bin-<arch>.tar.xz` 双包解压，符号链接用 `Os.symlink` 还原；JNA 按 ABI 挑 natives）；`patchJava` 做 Pack200 解包、libfreetype 改名、用 APK 自带 `libawt_xawt.so`/`libjsound.so`（OpenAL 后端）替换 JRE 内缺失/不可用库。进度文案做了 50ms 节流防刷爆主线程。全部完成后自动 `enterLauncher()`。`enterLauncher()` 在 IO 线程 `RendererManager.init` → `JavaManager.init` → `Controllers.init` → `ConfigHolder.init`，并做"每 3 天清理一次 CACHE_DIR 父目录"，随后把外部打开的整合包复制到 cache 并以 `modpack_cache_path` extra 跳 MainActivity（0 动画）。

**MainActivity**（1076 行，最重的页面）：装配 `UIManager(this, uiLayout)`（ui 包，垂直 ViewPager2 承载 8 个页面：主页/版本管理/下载/控件/联机/设置/账户/版本列表），`registerDefaultBackEvent`：已在主页时回桌面并 `exitProcess(0)`（直接杀进程），否则切回主页。`onKeyDown` 拦截返回键交给 `_uiManager.onBackPressed()`。点击菜单走 `onSelect`→`switchUI`；滑动翻页经 `pageSelectedListener` 反向同步左侧菜单高亮与标题。特色交互：双指在右侧栏区域内水平滑动收起/展开右菜单（dispatchTouchEvent 只分析不消费）；长按版本卡弹 VersionSwitchPopup 快速切换（并 `Profiles.registerVersionsListener` 在列表变化时重预热）；长按启动键弹 RendererSelectDialog；长按 home 键分享最新游戏日志；长按 back 打开 ShellActivity。启动入口 `launchVersion`：先查 `Controllers.isInitialized()`（未初始化则晃动按钮提示），`QuarkPromo.interceptLaunch` 包装，按版本设置选 DriverPlugin，刷新屏幕尺寸后 `Versions.launch(...)`（ui 包负责构造 LauncherHelper）。其余：账户卡用 fakefx 绑定 `Accounts.selectedAccountProperty` + `TexturesLoader.avatarBinding`；版本卡在 IO 线程做 `LibraryAnalyzer.analyze` 拼接"MC 版本+加载器"描述；DownloadManager 的 StateFlow collect 驱动右侧下载面板与波浪进度（有任务自动展开、无任务收起）；通知点击 `EXTRA_OPEN_PANEL` 在 uiManager 未就绪时先排队（`pendingOpenDownload`）；视频背景（`FCLPath.LIVE_BACKGROUND_PATH` 存在则 MediaPlayer 循环，音量读 SharedPreferences）；首次进入按 animationSpeed 延迟弹 GuideUtil 新手引导。

## 三、启动游戏全链路（game 侧）

**LauncherHelper**（`game/LauncherHelper.java`）是编排核心，构造时即建 `TaskDialog`。`launch()` 先 show 弹窗，`Task.runAsync(launch0)` 兜底捕获链构建前的异常。`launch0` 用 fclcore Task 链组装（`withStage` 对应弹窗 6 阶段）：
1. `launch.state.version`：`MaintainTask.maintain(repository, getResolvedVersion)`；
2. `launch.state.mods`：全量扫描 mods（一次扫描供 lwjgl3ify 补丁/加载器/渲染器检查复用，失败返回 null）→ `Lwjgl3ifyPatcher.patchIfNeeded` → `unmarkVersionLaunchedAbnormally`（.abnormal 标记，配合崩溃侧 `markVersionLaunchedAbnormally`）；
3. `checkGameState`（`launch.state.java`）：LibraryAnalyzer 识别 Cleanroom（>=0.5.0 要 Java 25，否则 jre21），Java 选 "Auto" 时 `JavaManager.getSuitableJavaVersion`；`isNotCheckJVM` 可跳校验，不匹配时弹三选（改自动/继续/继续并不再检查）；
4. `launch.state.dependencies`：`checkGameCompletionAsync`（完整性校验，`isNotCheckGame` 可跳）+ 整合包 completionTask；随后两个 `thenComposeAsync` 从 assets 释放 **MioLibPatcher.jar / MioLaunchWrapper.jar** 到 LIB_PATCHER_PATH / MIO_LAUNCH_WRAPPER，再按游戏版本执行 `GameVerificationFixTask`；
5. `launch.state.logging_in`：`logIn()`，微软账户挂 `setProgressCallback` 把认证阶段实时写进弹窗日志；`CredentialExpiredException` 弹 TipReLoginLoginDialog（重登/离线跳过），普通 `AuthenticationException` 弹 SkipLoginDialog（重试/离线/取消）——均用 `CompletableFuture` 把主线程对话框结果接回任务链；
6. `launch.state.waiting_launching`：读 menu_setting.json 取 `windowScale`，`repository.getLaunchOptions(...)` 构建 LaunchOptions；new **FCLGameLauncher**（扫 libraries 里最高 LWJGL 版本与 JNA 版本 set 进 launcher）；`launcher.launch()` 返回 **FCLBridge**；随后串 5 个人工确认点（每个都是"主线程弹 AlertDialog + CompletableFuture 阻塞链"模式）：checkPathValid（版本 jar 路径含非法字符）、checkRenderer（渲染器与 MC 版本区间，Angelica+lwjgl3ify 跳过）、checkNativeLibPlugin、checkModLoader（有 mod 无 loader 时可跳转安装页）、checkMod（ModChecker 逐 mod 校验，汇总 `bridge.setModSummary`）；再写 options.txt 的 preferredGraphicsBackend/startedCleanly；最后 `thenAcceptAsync` 主线程：`nativeSetUseInputStackQueue`、给 bridge 设 scaleFactor/controller/gameDir/java、`JVMActivity.setFCLBridge(fclBridge, MenuType.GAME)`、附加 TERRACOTTA_PLAYER extra、startActivity(JVMActivity)，顺带停掉主页视频背景、按 `autoExitLauncher` 设置 finish 主界面。

**FCLGameLauncher extends DefaultLauncher**：launch 前做大量"配置消毒"——生成 options.txt（首次从 assets 复制并按系统语言设 zh_cn/en_us）、关 Forge 加载动画 splash.properties、按版本修 lang 大小写（<1.11 大写国别码）、1.13- 清理全屏按键绑定、按当前渲染器对 Sodium/Rubidium/Draconic/Pixelmon/ImmersiveEngineering 配置写入关闭 shader/stencil 的兼容项。

**FCLGameRepository extends DefaultGameRepository** 是 FCL 对 fclcore 的关键扩展：① `getGameDirectoryType`/`getRunDirectory` 覆写实现版本隔离——整合包版本（beingModpackVersions 或 modpack.cfg 存在）强制 VERSION_FOLDER，否则看 VersionSetting.isIsolateGameDir；② 版本级设置：每版本 `fclversion.cfg`（`localVersionSettings` ConcurrentHashMap，`getVersionSetting` 为 null/usesGlobal 时回落全局，且读路径会顺手把全局的 usesGlobal 修正为 true 但"仅在错误时写"避免列表滑动反复触发保存）；③ 性能缓存：`resolvedVersionCache`、`modpackConfigCache`（refreshVersionsImpl 时清空，还负责补写假的 `launcher_profiles.json` 供 Forge 安装器用、重载本地设置、给整合包 specialize）；④ `duplicateVersion`、`clean`、`markVersionLaunchedAbnormally`（.abnormal 哨兵文件）、`getAllocatedMemory`（自动内存：预留 384MiB，≤8G 取 80%，超出部分取 20%，上限 16G）；⑤ `getLaunchOptions` 组装内存/分辨率（窗口缩放、强制分辨率 initForceResolution 写 FCLBridge 静态字段）/服务器直连/渲染器/debugLog 等参数。

**Lwjgl3ifyPatcher**（GTNH 兼容）：检测 mods 里启用的 lwjgl3ify（按 modid，改名不影响），从 jar 内嵌 `me/eigenraven/lwjgl3ify/relauncher/version.json` 读出 RFB 入口版本，**只改内存中的 Version 对象不落盘**（保持磁盘 JSON 纯净，补丁随 mods 自动生效/失效）；从内嵌 forgePatches.zip 离线还原库文件（临时文件+原子 rename）；强制写 `config/lwjgl3ify.cfg` 的 `linuxCreateAppDesktopEntry=false`（注释说明不写会因 Android 无 XDG 目录抛 RuntimeException 静默杀 RFB 主线程）；对历史上曾落盘补丁的存量实例，从 `.before-lwjgl3ify` 备份还原。

**JVMActivity**（游戏/Jar 执行器共用，静态持有 `fclBridge`+`menuType`——由启动方在 startActivity 前 set，故进程内单游戏）：TextureView.SurfaceTextureListener；`onSurfaceTextureAvailable` 首次时才是真正拉起点：`fclBridge.setSurfaceDestroyed(false)` → 按 MenuType 算宽高（GAME 时加 cursorOffset、乘 scaleFactor，FORCE_RESOLUTION 时用配置分辨率）→ 写 options.txt 的 overrideWidth/Height → `setDefaultBufferSize` → SDL 初始化（`SdlBridge.prepareSurface`）→ **`fclBridge.execute(nativeSurface, menu.getCallbackBridge())` 拉起 native JVM** → setSurfaceTexture/pushEventWindow。surface 复活路径（isRunning=true）走 setSurfaceTexture+setupBridgeWindow 重绑。`voteMaxRefreshRate` 请求最高刷新率；软键盘弹出时按可视区域把 TextureView 上移（可被 MenuSetting.isDisableSoftKeyAdjust 关闭）；`onSurfaceTextureUpdated` 第 2 帧才调 `menu.onGraphicOutput()`（隐藏启动遮罩）。生命周期向 GLFW 桥同步 FOCUSED/HOVERED/VISIBLE 窗口属性；返回键在输入法关闭时转发 ESC；音量键短按展开/收起左右抽屉（GameMenu）；`setRequestedOrientation` 被硬编码锁横向（对抗 SDL 动态请求方向）；特殊桥接 `messageboxShowMessageBox`（SDL 原生层在运行时类上按名查找该方法，非 SDLActivity 子类必须手动转发，否则 pending exception 导致 JniAbort）；onDestroy 做 `Terracotta.setWaiting`、`CallbackBridge.resetInputState`、`SdlBridge.reset()`、TTS shutdown。崩溃路径不在 Activity：GameMenu/JarExecutorMenu 的 `onExit(exitCode)` 中 `exitCode != 0` 时 `JVMCrashActivity.startCrashActivity(...)`，然后 `Process.killProcess(myPid())`。

**JVMCrashActivity**：Manifest 声明 `android:process=":crash"`，崩溃后游戏进程被杀、崩溃页跑在独立进程，FLAG_ACTIVITY_CLEAR_TASK|NEW_TASK 清空任务栈。展示完整日志（>8MB 拒绝读并提示手动查看）、识别 Fabric 不兼容 mod 段落（正则抓 FabricGuiEntry.displayError 区块弹专门对话框）、`findFatalErrorLogPath` 找致命错误日志。四个按钮：重启（跳 SplashActivity + NEW_TASK|CLEAR_TASK + 杀自身进程）、关闭（杀进程 exitProcess(10)）、上传日志（log + fatalLog 走 uploadLog）、分享。细节：`:crash` 进程冷启动时 applySavedNightMode 时机不对，需 `ThemeEngine.registerEvent` 显式按主题设背景色；按 `allowScreenshots` 决定 FLAG_SECURE。

**Jar 侧**：`JarExecutorHelper.start` 用文件选择器选 jar，读 MANIFEST Main-Class 的 class 文件魔数与 majorVersion 推断所需 Java 版本并就近映射（>21→25 等），可被全局设置 Java 覆盖；`JarExecutorLauncher` 生成 Cacio 命令行（Metal LookAndFeel、`-Duser.home` 指向游戏目录父目录、tmpdir 指 CACHE、lwjgl libname 占位），固定 GL4ES 渲染器，`FCLauncher.launchJarExecutor` 返回 bridge 后同样 `JVMActivity.setFCLBridge(..., MenuType.JAR_EXECUTOR)` 启动。

## 四、SDL 集成与手柄（game/sdl）

**SdlBridge**（object，移植自 ZalithLauncher2）：启动器与游戏 JVM 共享的 SDL 状态桥。`prepareSurface`（MainThread）首次 `SDL.initialize + SDLActivity.externalInitialize(SDLSurface,...)` 把 SDL 挂到 TextureView 的父布局与同一 Surface 上（SDL_Init 真正发生在游戏 JVM 侧），后续只 `SDLSurface.setNativeSurface`。维护 `sdlEnabled` StateFlow、surfaceGeneration、WeakReference 持 activity/layout；`isSdlRenderActive`/`setNativeTextInputActive` 为 external 方法（MC 26.3+ SDL 渲染路径 vs 26.2 Controlify 仅手柄子系统的区分、输入通道代激活）；`reset()` 全量清态。surface 尺寸变化时 JVMActivity 同步调 `SDLSurface.nativeResize`。**SdlSettings**：SharedPreferences "launcher" 里的 `sdl_auto_show_ime`、`gamepad_input_mode`（MAPPED=布局重映射 / SDL_DIRECT=直通）、`gamepad_input_mode_prompted`，全部 StateFlow 暴露。**DirectGamepad**：SDL_DIRECT 模式下把 Android KeyEvent/MotionEvent 轴直接写入 `CallbackBridge.sGamepadButtonBuffer/sGamepadAxisBuffer`（GLFW 按钮序号映射、0.85 触发阈值、HAT 轴转方向键）；**GamepadModePromptDialog**：首次手柄输入时单例弹窗选模式（确认前吞掉所有手柄输入），`DirectGamepadEnableHandler` 是游戏请求 direct gamepad 的回调接口。

## 五、setting 包：配置模型与单例群

- **ConfigHolder**：`config.json`（FILES_DIR）单例加载；`Config.fromJson` 带旧版下载源迁移逻辑（downloadType/autoChooseDownloadType/versionListSource → fileDownloadSource/versionListSource 枚举）；保存走 `InvocationDispatcher` 合并+专用线程 `FileUtils.saveSafely`（防抖、原子写），Config 任一 fakefx 属性失效即 markConfigDirty。
- **Config**：selectedProfile/commonDirectory/下载线程数与开关/下载源×2/`configurations`(TreeMap<name,Profile>)/selectedAccount/accountStorages/authlibInjectorServers/uiVersion 等。
- **Settings**（包私 init，由 ConfigHolder.init 调用）：一次性 init 四件套——`DownloadProviders.init(); Accounts.init(); Profiles.init(); 后台线程 Controllers.init(); AuthlibInjectorServers.init()`，并装配 FCLCacheRepository。**这就是 setting 侧的总初始化器**。
- **Profiles**（object，Kotlin 重写版）：profiles 列表 + `selectedProfile`/`selectedVersion` 两个 StateFlow（替代原 fakefx ObservableList/ListProperty）。空列表时自动造两个默认 Profile：共享目录（SHARED_COMMON_DIR）与私有目录；`addProfile/removeProfile` 统一入口触发 `updateProfileStorages`（TreeMap 写回 Config.configurations）与选中项校验；`setSelectedProfileInternal` 写 `.nomedia`、bindSelectedVersion、只对未加载仓库的 Profile 做异步 refreshVersions（已加载的保留缓存加速切换）。versionsListeners 供 MainActivity 预热快切弹窗。
- **Profile**（Kotlin）：`gameDir` setter 直接 `repository.changeDirectory`（注释强调 repository 必须先于 gameDir 初始化）；`selectedVersion` setter 做 `checkSelectedVersion`（不存在时回落第一个版本）+ 同步通知监听；`getDependency()` 每次 new DefaultDependencyManager（下载源取 DownloadProviders 单例 wrapper）。
- **VersionSetting**（Kotlin，344 行）：全字段含 usesGlobal/java("Auto")/maxMemory/minMemory/autoMemory/javaArgs/minecraftArgs/notCheckJVM/notCheckGame/serverIp/isolateGameDir/graphicsBackend/VKDriverSystem/controller(默认"00000000")/renderer(默认 NGGL4ES)/driver(默认"Turnip")/notCheckMod/debugLog/forceResolution；**已从 fakefx property 迁移为普通字段 + `addOnChangeListener` 手写监听**（每个 setter 判等后 `changed()` 复制遍历通知）；自写 Gson Serializer（java 字段反序列化时校验存在性回落 "Auto"；maxMemory<=0 时按设备推荐值）；`checkController()` 挂 Controllers 回调把失效控件 id 修正为第一个控件。**MenuSetting**（351 行）：游戏内菜单全量字段（窗口缩放 windowScale、cursorOffset、鼠标/陀螺仪/手势/性能模式/控件不透明度/吸附等），同样手写序列化，存 `menu_setting.json`。
- **Controllers/Controller**（控件管理）：Controllers.init 在后台线程扫 CONTROLLER_DIR 的 json，**轻量解析**（`Controller.parseLightweight` 流式 JsonReader 只读元数据与布局 id/name/visibility，不实例化按键），controllerVersion 超出 [MIN, CURRENT]（当前 21）的文件跳过、损坏文件改名 .bak；`loadViewGroup` 异步按需补全布局按键数据（后台解析、模型填充统一回主线程，因 fakefx 列表监听非线程安全）；`addCallback` 让未就绪时的调用排队到主线程执行（VersionSetting.checkController 依赖它）。Controller.saveToDisk 用 dirty/active 双 AtomicBoolean 实现"合并保存"：已有保存任务时只置 dirty，任务收尾循环检查再写一遍，防丢最新修改；序列化前 `ensureAllLoaded`（后台时用 CountDownLatch 等主线程补全）防止轻量对象把按键清空。文件名与 id 不一致时自愈 rename。
- **Accounts**：三类工厂（offline/microsoft/authlibInjector）+ `OAUTH_CALLBACK = new OAuthServer.Factory()`；账户双存储——portable 进 config.accountStorages，全局进独立 `accounts.json`（GLOBAL_PREFIX "$GLOBAL:" 标记）；init 时后台预登录选中账户、后台拉取 authlib 服务器元数据、触发 authlib-injector 更新检查；`localizeErrorMessage` 巨型异常→文案映射。
- **DownloadProviders**：Mojang/BMCLAPI 双源，`AutoDownloadProvider` 按"版本列表源/文件下载源"两个偏好各配候选链（DEFAULT 按地区排序），wrapper 暴露；init 用 `FXUtils.observeWeak` 挂在 Config 属性上热切换，并同步下载并发数。
- **GameOption**（Pojav 来的 options.txt 读写器）：静态 parameterMap + 全局唯一 FileObserver（MODIFY 事件重载并通知 WeakReference 监听），save 时先停 observer 防自触发。
- **GlobalConfig**（agreementVersion/multiplayerToken，Serializer 保留未知字段防丢）、**AuthlibInjectorServers**（首次运行导入 assets 侧 `authlib-injectors.json` 批量添加服务器）、**DownloadSource**（DEFAULT/OFFICIAL/MIRROR 枚举）。

## 六、upgrade 升级机制

**UpdateChecker** 单例：URL 按语言选 GitHub raw `version_map.json` 或 Gitee 镜像；`check()` 用 AtomicBoolean CAS 防重入；顺带把最大 versionCode 条目的网盘链接喂给 QuarkPromo；扫描第一个 versionCode > 当前且非 beta 且未被忽略（`ignore_update` 存 SharedPreferences）的版本弹 UpdateDialog；`showCurrentChangelog` 供设置页"查看更新内容"。**RemoteVersion**：type(beta/release)/versionCode/versionName/date/多语言 description/url/netdiskUrl。**UpdateDialog**：正按钮用 TaskDialog 下载 APK 到 CACHE_DIR（URL 按 CPU 架构把 `-all` 替换成 `-arm64-v8a` 等），完成经 FileProvider 拉起安装器；失败弹窗兜底"走网盘"；忽略按钮写 ignore_update；长按正按钮直达 GitHub Releases。**ChangelogDialog** 为只读版本（高度自适应：不足一屏收缩，超屏限高滚动）。

## 七、terracotta 联机、scoped、util

**Terracotta**（联机 UI 侧封装，底层 `net.burningtnt.terracotta` 库）：`initialize` 后起一个**守护线程死循环每 0.5ms 轮询** native `getState()` JSON，用 index 单调性去重后 CAS 进 `AtomicReference` 并经 InvocationDispatcher 派发到主线程的 ReadOnlyObjectProperty——UI 层只需订阅 stateProperty。状态机 `TerracottaState`：waiting/host-scanning/host-starting/host-ok/guest-connecting/guest-starting/guest-ok/exception（JsonType 多态，HostOK/GuestOK 携带房间码与玩家 profile 列表，`isForkOf` 用 index 差做状态回退判断）。VPN：`TerracottaVPNService`（前台服务）持有 `TerracottaAndroidAPI.getPendingVpnServiceRequest().startVpnService(builder)` 建的 tun（`addDisallowedApplication` 排除自身包）；通知随状态经 ACTION_UPDATE_STATE 更新，deleteIntent 走 ACTION_REPOST 自愈重建通知；onRevoke/onDestroy 回 `Terracotta.setWaiting`（JVMActivity.onDestroy 也调用它——游戏退出时复位联机状态）。**TerracottaNodeList** 拉取 `terracotta.glavo.site/nodes` 节点表（按 region 与是否中国大陆匹配过滤，double-check 锁缓存）。

**scoped/FolderProvider**（DocumentsProvider）：把应用 data 目录与 Android/data 以文档根暴露给系统文件管理器/第三方（docId 前缀 `data`/`android_data`）；判存在用 `Os.lstat` 而非 File.exists（注释：链接目标不可访问时 exists 会误判）；额外支持 MT 管理器私有扩展 call 方法（mt:setLastModified/mt:setPermissions/mt:createSymlink）与 mt_extras 列（mode|uid|gid|readlink）。

**util**：`Constants`（CONTROLLER_VERSION=21、MIN=0）；`RequestCodes` 全部 startActivityForResult 请求码表；`FXUtils`（onInvalidating/observeWeak 弱监听、EditText↔Property 双向绑定的 EditTextBindingListener，用 identityHashCode 做 equals）；`RuntimeUtils`（上文运行时安装/解压/patchJava）；`ShellUtil`（`sh` 长驻进程、清空环境变量、HOME 指向 files 父目录，供 ShellActivity 调试）；`ModTranslations`（枚举 MOD/MODPACK，懒加载解析 mod_data.txt/modpack_data.txt 为 curseforge/modId/subname 多索引，searchMod 用 LCS 相似度；被 LocalizedRemoteModRepository 用来把中文搜索词翻译成英文关键词重查 CurseForge/Modrinth，中文命中前置排序）；`WeakListenerHolder`（强引用弱监听器防止被回收）；`TaskCancellationAction`、`ResourceNotFoundError`。

**WebActivity**：微软登录 WebView；本地 OAuth 回调（`localhost(:port)/auth-response`）在 onPageStarted 检测到即 finish（注释强调不能在 shouldOverrideUrlLoading 拦截否则回调请求发不出去）；设备码轮询完成事件与 LoginFinished 事件双保险关页；onDestroy 显式 unregister 强引用监听（注释：registerWeak 配对的 unregister 摘不掉）。**OAuthServer**：NanoHTTPD 起 29111-29115 端口池收授权码，`openBrowser` 特意不给 otc 参数自动填充（第一方预授权会 invalid_request）。**ControllerActivity**：无 bridge 的 GameMenu 独立预览/虚拟手柄页。

## 八、跨进程/跨线程机制与值得注意的点

1. **多进程**：主进程 + `:crash`（JVMCrashActivity）+ `:jvm`（fclcore ProcessService，下载/进程作业）。崩溃链是"游戏进程自杀 + 新进程起崩溃页"，靠文件（logPath）而非内存传递数据；重启按钮先 startActivity 再 killProcess 保证跳转落地。
2. **任务链与对话框的桥**：LauncherHelper 的模式是后台 Task 链中 `CompletableFuture` + 主线程 AlertDialog 完成人工决策，同一模式出现在 Java 版本校验、渲染器/插件/mod 检查、登录重试。所有弹窗失败都按异常类型做精细文案（DownloadException/404/超时/AccessDenied/ModCheck…）。
3. **假单例与静态态**：JVMActivity.fclBridge/menuType/isRunning 为 static，依赖"启动前 set"；SdlBridge/GameOption(fileObserver, parameterMap static)/UpdateChecker 均有进程级全局状态，`:crash` 进程会重新走 FCLApp 初始化。
4. **线程安全细节**：Controllers 的 LOCK 串行化后台 init 与主线程读；Controller 保存的 dirty/active 双标志；fakefx 列表监听要求模型填充必须在主线程（多处注释强调）；Profiles/VersionSetting/MenuSetting 改动通知都用"复制后遍历"防并发修改。
5. **坑/实现取舍**：MainActivity 返回键在主页时直接 `exitProcess(0)`（非 standard 后台）；`Profiles.init` 里 `holder`（WeakListenerHolder）注册的 RefreshedVersionsEvent 弱监听器靠 holder 强引用保活；`GameOption` 的 FileObserver 与 parameterMap 是 static，多实例共享一份 map（构造不同 gameDir 会互相覆盖）；`JVMActivity.isRunning` 只置位不复位，进程存活期内二次进游戏走 surface 复绑路径；`VersionSetting.Serializer` 反序列化 `isolateGameDir` 默认 false 而字段默认 true（新旧配置语义差异）；`SplashActivity` 的 Fragment 事务用 `commitAllowingStateLoss`（注释已说明后台恢复场景）。
